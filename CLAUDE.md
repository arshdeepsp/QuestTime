# CLAUDE.md — ProductivityCraft

Pixel-art gamified habit/productivity app. Web PWA (GitHub Pages) + Android app (Capacitor). Data lives on the device; an optional account (Firebase Auth + Firestore) syncs it between devices.

## Working with Arsh
- Keep answers short; lead with the answer.
- Pastable commands contain no comments; explain in prose outside the code block.
- Run only the specs that cover a change (`npx playwright test tests/<spec>.mjs -g …`), not the whole suite — a full run costs ~4 min and he doesn't want it on every prompt; keep the full `npm test` for wide or risky changes. Add a test for every behaviour change or bug fix.
- He tests on a real Android phone; native code can only be verified there.
- Commits are authored as Arsh (`git -c user.name=… -c user.email=…` taken from the last commit), one commit per batch, ending with the `Co-Authored-By` and `Claude-Session` trailers; he pushes himself.
- **Cloud-session workflow**: the Mac's mounted repo can't build (`cpSync` EACCES) and the linked VM has no Chromium, so builds and tests run in a container mirror (`/home/claude/pc`), moved there as a tarball (`tar czf … --exclude node_modules --exclude dist --exclude test-results --exclude ./android --exclude ./native --exclude .git .`) and back file by file (`device_commit_files`, md5-checked; or a tarball unpacked with `device_bash`). **Never run `npm install` from the VM** — it would put Linux binaries (esbuild is platform-specific) into the Mac's `node_modules`; Arsh runs it on the Mac. The link drops often: re-verify checksums and `git status` before committing, and re-request delete permission after a drop. `pkill -f <pattern>` kills the shell itself if the pattern appears in its command line; run long suites under `nohup … > /tmp/full.log &` and poll the log.

## Commands
```
npm install
npx playwright install chromium
npm run build
npm run format
npm test
npm run serve
npm run android:apk
```
- `build` → `dist/` (single `index.html` + assets + `sw.js` with versioned cache; the version hashes `index.html` and `vendor/firebase.js`). It also bundles `src/firebase/fb.js` + the Firebase SDK with esbuild into `dist/vendor/firebase.js` (ESM, loaded lazily on sign-in; listed in the service worker's assets).
- `format` → Prettier 3 (`.prettierrc.json`: print width 120) over `src/js`, `src/styles`, `src/firebase` and `build.mjs`; run it before committing (`format:check` reports without writing). Source is formatted for reading; the build bundles the JS (esbuild, from `src/js/main.js`) and whitespace-minifies it and the CSS (comments dropped), so formatting doesn't grow the app. `tests/` isn't formatted.
- `test` → build + Playwright (headless Chromium, fake clock, seeded localStorage), served over http by `tests/serve.mjs` on :4173 (file:// lost localStorage across reloads and made reload tests flaky). ~350 tests, ~4 min (`--workers=2` in the container).
- `android:apk` → build, `npx cap sync android`, `node scripts/add-native.cjs`, `./gradlew assembleDebug`. Never run `assembleDebug` alone after source changes.
- First Android setup: `npx cap add android`, `node scripts/add-permissions.cjs`, `npx @capacitor/assets generate --android`, then `npm run android:apk`.
- Push to `main` → GitHub Actions runs tests, deploys `dist/` to Pages only if green.

## Layout
```
src/index.html         markup with /*@inject:css|ach|js*/ points
src/styles/NN-<screen>.css  one file per screen, joined in number order (= cascade order); see Design system
src/js/<feature>/*.js  ES modules; src/js/main.js is the entry (esbuild bundles it); see below
src/assets/achievements.json
src/firebase/fb.js     facade over the Firebase SDK (window.PCFB); the only file that imports firebase
firestore.rules        users/{uid}/** readable/writable only by that uid; deploy with firebase-tools
public/                static files copied to dist (fonts, icons, vendor, manifest, sw.template.js)
native/android/        FocusNotifier/FocusNotifyPlugin/FocusNotifyReceiver (Java), layouts, icon, pc_chime.wav
scripts/               add-native.cjs, add-permissions.cjs (.cjs because package.json is "type": "module"); check-js.mjs; css-diff.mjs
tests/*.spec.mjs       Playwright specs; helpers.mjs has openApp() and dayRange()
build.mjs              the whole build
```
- **`src/js` is ES modules**, grouped by feature: `core/` (state and store, dates and the day window, config, storage, migrate, boot), `rules/` (which quests are on a day, day rules, `compute`, modes, XP, period totals, frozen past days, easing), `quests/` (list, phone rows, row menu, editor, new quest, to-dos, daily limit, finish lines, starter packs), `timer/` (focus timer, sprint, sessions, live notification), `schedule/`, `subjects/`, `progress/` (badges, grove, trends, share, wrap-up, reset card, past day), `notifications/` (plan + sync, taps), `settings/`, `sync/` (account, auth pages, merge, backup), `rulebook/`, `tools/`, `ui/` (render, navigation, themes, gestures, modal, menus, feedback, help, splash…). Each module imports by name exactly what it uses and exports its functions and variables; the build bundles `main.js` with esbuild into the page (`format: iife`, whitespace-minified; `./vendor/firebase.js` stays an external dynamic import).
- **Startup order**: no module runs anything when imported. A **numbered** file (`NN-…`/`NNb-…`) keeps its startup code (listeners, first renders, values of its `export var`s) in `export function init()`, and `main.js` calls every init in file-number order, which is the order the app has always started in; a value used during startup must be set by an earlier init (this has bitten us). An **unnumbered** file holds only functions. Top-level variables are `export var x;` (no value at the top; assigned in `init`). **Variables several modules reassign live on `G`** (`core/g.js`, `export const G = {}`): an imported binding can't be reassigned by its importer, so `qSig`, `timer`, `storeHold`, `cacheBlock`, the schedule's `schSel`/`schMsg`/…, the `*Open` panel flags and the like are read and written as `G.qSig` etc. (54 of them; a new one that another module must write goes on `G` too). `scripts/check-js.mjs` (in `npm test`, or `npm run check:js`) enforces: only imports and exports at the top level, `init` only in numbered files, `main.js` imports and calls every init in order, unique file names and top-level names. The conversion (2026-10) moved every startup statement into `init` in its original order; the full suite, `css-diff.mjs` (0 differences in 438 states) and the crawl matched the old build. It also exposed three bugs that only ran in sloppy mode: `wrapCanvas2` read `np` from another function (the wrap-up PDF always failed with "PDF engine didn't load"), the 1004 "Time's up" tap read an undefined `extra`, and Trends wrote an undeclared `qs`.
- Two dist-only artifacts exist outside the repo (old claude.ai artifact, old `productivitycraft-android` folder). Both are retired; this repo is the only source.

## State and data
- Global `S` = `{days, refl, cfg, meta, timer, sprint, ...}`; persisted via `cache()` (= `store.flush()`) to the active copy: `storeKey()` = `pc-cache-u-<uid>` while signed in, else `pc-cache-v1` (the guest copy).
- **Data is linked to accounts**: each account signed in on this device has its own copy; only the signed-in one is loaded. Switching never swaps state in place: `enter()` (sync/54-account.js) / sign-out / deletion set `storeHold` (the local adapter stops writing), adjust the copies and `pc-account`, leave a note in `sessionStorage["pc-authnote"]` and reload (`reloadApp`); 55 shows the note on the gate or as a `setSync`. Sign-up moves the guest copy into the new account; sign-in moves it only when the account has nothing in the cloud (no `data/cfg`, no days), otherwise the guest copy stays apart and the account starts from its own copy (or empty, then `merge` pulls). Sign-out deletes the account's copy and wipes Firestore's offline cache (`fb.js` `terminate` + `clearIndexedDbPersistence`); it's refused while a timer/sprint runs (`app/timer`) and asks first when `cloud.unsynced()` (queue, push in flight, or not "on") — Settings arms "Sign out anyway". A session ended elsewhere (`onAuth(null)`) keeps the copy, hidden, for the next sign-in. Account deletion removes the copy too. One-time upgrade: the first load with `pc-slots` unset moves `pc-cache-v1` into the signed-in account's copy. The welcome waits for the first merge when signed in.
- **Document store** (`store` in `core/00-state.js`): the state is a set of docs — `cfg`, `refl`, `days/<date>` (and `session` = timer/sprint, device-local, never synced). `store.flush()` diffs by object identity against the last flush, stamps changed docs in `S.meta.u[doc] = Date.now()` and deleted days in `S.meta.del[doc]` (tombstones), then hands the whole state and the changed ids to the adapter (`localAdapter` saves to localStorage; `cloudAdapter` in sync/54-account.js wraps it and queues pushes). So **replace, never mutate**: `saveCfg(clone)`, `S.refl = Object.assign({}, S.refl, …)`, `S.days[k] = Object.assign({}, e, …)` — an in-place edit is invisible to the diff and never saved or synced. `store.adopt(id, obj, u)` installs a doc that came from the cloud without re-stamping it. Tests: `tests/store.spec.mjs`.
- `cfg()` returns settings; change settings with `saveCfg(clone)`. `saveCfg` drops repeated quest ids (`dedupeQuests`, core/config.js); launch repairs saved settings that have them (core/49b-boot.js, saved as an edit so a signed-in device pushes the fix), a cfg adopted from the cloud is de-duplicated and the repair pushed back, and `mergeIds` never repeats an id. Edit today via `entry()` then `commit()`.
- **Store subscriptions**: `store.subscribe(fn)` (core/00-state.js) calls `fn(ids)` after every save that changed documents (`cfg`, `refl`, `days/<date>`, `-days/<date>` for a removed day) and after `store.adopt` of a cloud document (`store.emit`). `ui/04-render.js` subscribes `onStoreChange`: the next microtask calls `render()` unless something already rendered since the change (`renderSeq`), and saves made while rendering (`rendering`: past-day snapshots, housekeeping) don't schedule another. So a change re-renders on its own; an explicit `render()` still works and is immediate ("Show plan" in Settings relies on the subscription; its test is in store.spec). Call `render()` yourself when the order matters: the cloud pull renders before its own `cache()`/push, because freezing past days during render changes docs that must go out with that push (a deferred render made a remote edit lose a merge). Set `G.qSig=""` when the quest list's structure changed in a way `activeDefs` doesn't show.
- Each day entry stores a snapshot of its quest defs in `e.q` (`slim()` decides which fields are copied — add new quest fields to that list).
- **Past days are frozen** (`lockPast`, 26, run at the start of `render` and `compute`): every passed day without a snapshot gets `e.q = activeDefs(k)` as it stood when the day ended, plus `e.ck` = ids of totals whose halfway checkpoint fell on it. So later edits, pauses and deletions never rewrite history. `dayDefMap(d)` = quests on day d (snapshot for past days, live for today on). `hasEntry` ignores `ck`; `firstSeen` skips auto snapshots. Repeats that fell on a passed day are copied onto it (`lockReps`: one-offs with `src` + `schSkip`; `cfg.repFrozen` marks the one-time catch-up), so stopping a repeat never changes past plans. `lockPast` resets when `START_KEY` changes or after an import (`lockReset`) and is skipped while `cacheBlock`. SCHEMA 12 marks this. Import takes a backup's `q`/`ck` for days with nothing logged locally. SCHEMA 14: data upgraded from older versions gets `cfg.ckFrom` (upgrade day) — halfway checks only apply to periods starting on/after it, and older `ck` are cleared.
- **Pull to refresh** (`ui/56-pull-refresh.js`, `#ptr`, `15-splash.css`): on touch, pulling down from scroll top with nothing on top (`ptrBlocked`: schedule, help, account page, editor, grove, typing, menus, modals, drags, splash) past `PTR_GO` (64 px, pull damped by half) and letting go calls `appRefresh(note?)`: `cache()`, `storeHold`, `sessionStorage["pc-quick"]` (ui/53-splash.js skips the splash once) and an optional note (`pc-authnote`, shown by sync/55-auth-pages.js), then `location.reload()`. Signed in, the reload's first sync pulls everything. **Import** (sync/05-backup.js) ends with `appRefresh("Imported …")` instead of re-rendering in place, so every screen and cache starts from the imported data; it also no longer mutates `S.cfg` after `saveCfg`. Tests: `tests/refresh.spec.mjs` (the fake cloud now lives in `tests/fakecloud.mjs`, shared with sync.spec).
- Unreadable saved data, or data from a newer schema, is copied to `pc-cache-rescue` and `cacheBlock` stops `cache()` from writing over it (a modal explains) until a backup is imported.
- `SCHEMA` in `core/00-state.js`, `migrate()` in `core/migrate.js`. Changing stored shape: bump SCHEMA, add a migrate step, add a test in `tests/data.spec.mjs`. Backups from a newer schema are refused. SCHEMA 18 dropped retired leftovers (`cfg.bank`, `cfg.capSet`, day `top`); the time bank, carried days (notification 2300, mark `carried`) and Top 3 are gone from the code too. `compute` runs `indexDays()` (rules/26-periods.js) to rebuild `eKey` (day entry → date).
- **Look and feel is account data** (SCHEMA 17): `cfg.ui` holds sound on/off (`sfx`), Minimal view (`focus`; a timer's forced Minimal never writes it), stats panel (`stats`), HUD details (`hud`), the Done/Off today/Ignored groups (`done`/`off`/`ign`), folded subjects (`sjfold`) and grove info (`groveInfo`); read with `uiGet(k, def)`, write with `uiSet(k, v)` (core/config.js). The SCHEMA 17 step copied the old localStorage keys (`pc-sfx`, `pc-focusview`, `pc-stats`, `pc-hudopen`, `pc-doneopen`, `pc-offopen`, `pc-ignopen`, `pc-sjfold`, `pc-groveinfo`) in, which is why `extra: {"pc-doneopen": "1"}` still works in tests on seeded (schema-less) data. A cfg arriving from another device runs `applyLook()` (ui/look.js) so theme, reduce animations, sound, Minimal view and the panels change at once. Theme, calm, idle grove, `hide`, style, tap sounds and vibration were already in cfg.
- Device-only prefs live in separate localStorage keys (`pc-adv`, `pc-todoreview`, `pc-rerate`, `pc-splash`, ...; `sessionStorage["pc-noacct"]` = chose "Use without account" for this launch). `pc-account` = `{uid, email}` of the signed-in account (read by `cloudAccount()` in core/storage.js so Settings can render before 54 loads).
- **Account and sync** (`sync/54-account.js`, Settings › Account): email/password via Firebase Auth; Firestore docs `users/<uid>/data/cfg`, `users/<uid>/data/refl`, `users/<uid>/days/<date>` (document paths must have an even number of segments; both fakes enforce it), each `{...doc, u, at}` (`u` = device stamp, `at` = server write time, added by `fb.js` with `serverTimestamp()` and handed to the app as ms); a deleted day is written as `{del:true, u}`. Config in `FIREBASE_CONFIG` (web app of project `productivitycraft`, region Toronto; `measurementId`/Analytics unused). The SDK loads only on sign-in (`cloud.lib()` → `import("./vendor/firebase.js")`), so signed-out users never download it. **Who wins is decided by content, not clocks** (`takeRemote`, helpers in `sync/merge.js`): `S.meta.h[id]` = hash (`hashOf`, canonical JSON) of the version both sides last agreed on (`agree`, after an adopt or a successful push), and `S.meta.cb` = that version of cfg. Only the remote changed → take it; only ours → push ours; both → `merge3`: cfg three-way against `cb` (lists of `{id}` merge item by item, an item removed on one side stays removed unless the other side edited it, new items go after their nearest surviving neighbour, plain-value lists like `ignore` merge as sets), days and reflections two-way (union of fields); the same field changed on both sides goes to the newer `u` (the only use of device stamps). The result is installed as a local edit and pushed. An edit beats a deletion from the other side. Docs with no agreed version yet (synced before this) fall back once to the newer `u`; a local doc that is empty (default cfg, `{}` refl, a day with no keys) never beats a remote one (`emptyLocal`), so a fresh device adopts the account's data. On sign-in `cloud.start` runs `pull()`, which is the full `merge()` (every remote doc, then push) the first time. **No live listeners** (real-time sync made +/- taps jump back when a stale doc landed mid-edit): a local flush queues the changed docs and `schedulePush` pushes them `PUSH_DELAY` (3 s) after the last edit, so a burst of taps is one write; going to the background (`visibilitychange` hidden) pushes at once. Other devices' changes are pulled on launch and on return to the app by `pull`: `fb.db.listSince` on `data` and `days` = docs whose server `at` is after `S.meta.pat` (newest `at` seen, saved in the account's copy so it goes with it) less `PULL_SLACK` (1 min), so a launch costs a few reads, not one per day ever logged, and no device clock is involved; our own pushes come back once. A full merge rewrites docs that have no `at` yet (written before it existed), so incremental pulls see them afterwards. Local docs stamped after `S.meta.synced` (when everything last reached the cloud) are queued on each pull, so an edit made just before the app closed still goes up. No `pat` (first use of the account on this device) → the full `merge`; Sync now is always the full merge. Test fakes count `__cloud.reads` (Firestore billing: a query returning nothing costs 1) and stamp `at` from their own counter (`__cloud.tick`, unrelated to the page clock); `__cloud.put(path, data)` is another device's write without the app noticing, `remote()` = `put` + a return to the app. `flushQueue` sets `cloud.state.status` on/syncing/error; a failed push stays queued and is retried on the next change or Sync now. Sign-out and Erase first `settle()` (push now, wait ≤ 6 s) before the unsynced check; the armed "Sign out anyway"/"Erase anyway" labels are drawn from `acOutArm`/`eraseArm` so a status re-render keeps them. The fake's `__cloud.remote()` also fires `visibilitychange` (a return to the app). Sign-out removes the account's copy (see "Data is linked to accounts"). **Account pages** (`sync/55-auth-pages.js`, `#authPage`, `14-auth.css`): a full-screen page with views `login | signup | reset | change | delete` (`openAuth(view, gate, note)`, `authGo`, `authErr` maps Firebase codes to plain text; show/hide on every password field). On every launch with no `pc-account` it opens as the **gate** (no Close; "Use without account" sets `sessionStorage["pc-noacct"]`, so it holds for this launch only and the next launch asks again; an old localStorage `pc-noacct` is removed; Android back minimizes); sign-out, account deletion and a session ended elsewhere reload into it with a note. The first-run welcome waits for it (`welcomeCheck` in ui/24-help.js). Sessions never expire: `fb.js` uses `initializeAuth` with IndexedDB (then localStorage) persistence, and only sign-out, deletion or a password change elsewhere end one. Sign-up sends a verification email (`sendEmailVerification`); Settings › Account shows "not verified" with Resend (`cloud.verify`) and Done (`cloud.refresh` → `reload`). Change password and Delete account reauthenticate with the current password (`reauth`); `cloud.deleteAccount` stops sync, removes every `users/<uid>` doc (`PCFB.db.remove`), then deletes the Firebase user and this account's copy on the device (`leaving` stops the SDK's own signed-out callback from reloading first). Both test fakes fire the auth callbacks on sign-out/deletion like the SDK. Reset never says whether an account exists. Tests: `tests/auth.spec.mjs` (own fake PCFB with accounts and a sent-mail log); `openApp` sets `sessionStorage["pc-noacct"]` unless `extra` has `pc-noacct` (`{"pc-noacct": ""}` shows the gate). **Erase this device** (Settings › Your data, armed twice; `cloud.eraseDevice(force)`): removes every `pc-cache-*` copy, `pc-account`, `pc-welcomed`, `pc-rerate`, signs out (clearing Firestore's cache) and reloads to the gate; same timer/unsynced guards as sign-out ("Erase anyway"). Firestore's persistent local cache gives offline queuing; there is no IndexedDB code of our own. Rules: `firestore.rules` — without them deployed every write fails with permission-denied. Tests (`tests/sync.spec.mjs`) install an in-memory fake `window.PCFB` in `addInitScript` with a `remote(path, data)` helper, so no network is needed.

## Core rules (keep tests green when touching these)
- **Day cleared**: every required quest met and no limit broken. Required (`reqOf`) = not optional, not weekly-X-times, not to-do, not a period total (`q.roll`). Nothing required → rest day.
- **Period totals are judged twice** (`periodCheck` in `compute`). Work days (`workOn`): on that day's list, scheduled, not off, not on vacation (paused days aren't on the list). Halfway: `midAt(q,k,now)` = the ceil(n/2)-th work day of the period (from the quest's start in a first period); once passed it's fixed by `e.ck`, and if a change would move it onto a day already gone it becomes today. You need `midNeed` = a third of the target (`MID_FRAC`), else the days so far are lost and the streak resets (`st.lost` entry with `mid:true`). At the end: on the last day of a total's period, if `rollSum < weekTarget` (prorated to work days, so a pause or deletion mid-period prorates it rather than skipping the check), every ok/grace/frozen day from `weekFrom` (the quest's start) becomes `lost` (no longer counted in `st.total`), freezes earned on them are taken back, and the streak resets (only if something was lost or a streak was running). Which totals are checked: every total seen on a day's list in the period (`seen` in compute; `periodList(k)` for UI), unless it's user-optional (`activeDefs` stamps `uopt` on optional totals, since off days also carry `opt`). `perWorkDays` counts each day with that day's version, so changing a total's days mid-period keeps its target. `st.best` = most ok days between resets, so lost days never count. `st.lost` records it. During the period `#carryNote` (`renderCarryNote`, rules/period-note.js) shows the next checkpoint for each total (a third by the middle work day, then the full total by period end); notification 2600 fires at 09:00 on the earliest checkpoint a total is short for (halfway if a third isn't done yet, else period end; off days included); the pace (`rollNeed`) is advisory.
- **Challenge and Casual modes**: Settings › Quests & rules › Mode, switch "Challenge mode" (`setStreaks`) opens/closes a range in `cfg.noStreak = [{from, to?}]` (`to` exclusive); a day is Casual inside a range, else Challenge: `noStreakOn(k)`/`rewardsOff()`/`noStreakIn(a,b)` in rules/modes.js. Asymmetric: Casual starts today (today becomes a Casual day at once); Challenge resumes from tomorrow (today during setup), so switching back can't rescue a failing day. Switching to Casual again while a resume is pending reopens the range. The switch shows tomorrow's state. **Challenge** = the full game: day cleared/streak, grace/freezes, period totals judged, easing changes from tomorrow, per-quest streaks, streak repair, badges, grove, streak-risk (2200) and checkpoint (2600) alerts. **Casual** keeps XP, level and rank (`totalXP`/`dayXP` count Casual days, `weekCountOn` counts their check-offs) but a Casual day is marked `pause` in `compute` (neutral like rest, so the streak picks up where it was), no total is judged in a period that touches one (`periodCheck`/`periodList` use `noStreakIn`), no badge progress (`badgeStats` skips it; nothing is awarded while Casual) and no grove gold; easing changes apply at once (`guardEasing`, `pauseQuest`). While today is Casual `body.nostreak` (rules in each screen's file) hides streak stats, the period note, the side badge card and the Badges/Grove tabs; Trends and the share card show days logged instead of cleared/streak; totals show only "Xh of Yh done this week" (no pace/"need" figures). SCHEMA 13 marks `noStreak`; SCHEMA 16 dropped Strict mode, rebase, the gate, commitment checks and change locks (`strict`, `easeLog`, `capSet`, quest `lock/lockFrom/pending`, day `brk`). **Ignore list** (Casual days only): `cfg.ignore` = quest ids; swipe right on a row (or row menu "Ignore"/"Add back to the list", `setIgnore` in rules/modes.js) toggles it, replacing swipe-right-to-done while Casual. `ignoredOn(id,k)` → `activeDefs` marks the quest `opt` + `ign`, so it's out of the count, the schedule (`schQuests`), repeats and their reminders, Just 5, Pick, open to-dos; rows sit in a collapsed "Ignored (n)" group (`#ignSep`, `.ignq`, `pc-ignopen`). Time logged on it still counts. Kept while the last Casual day runs out; cleared when a fresh Casual range starts (or on an immediate resume during setup). SCHEMA 15 marks `ignore`.
- **Per-quest streaks** (rules/quest-streaks.js): `qStreakable(q)` = time/check/target/scale/wake quests that aren't totals. `qDayState(id,d)` → met / miss / skip (not scheduled, paused, off, ignored, Casual, before `addedOn || firstSeen`); `qStreak(id,k)` counts consecutive met days back from k (today's pending miss doesn't break it), `qConsist(id,k)` = met ÷ scheduled over 30 days. Shown as the `.qstk` chip on rows (from 2 days) and in Details. Display only — the day streak is still `compute`'s.
- **Streak repair** (progress/21-reset-card.js, Challenge only): after a reset, `#resetCard` (`renderResetCard`, non-blocking, under the HUD for `RESET_CARD_DAYS` 3 days; Save/Skip write `S.refl[day]`) offers "Repair for 200 XP" when `canRepair(st)`: the day that reset it is a plain miss (`st.marks[k]==="miss"`, not a lost total) and `xpNet() >= REPAIR_XP`. `repairStreak(k)` sets `e.rep = true` on that day (counted as a success by `compute`, drawn `.strip i.repaired`; `hasEntry` ignores `rep`) and adds to `cfg.xpSpent`; `xpNet() = totalXP − xpSpent` drives level and rank.
- **Misses**: first miss = grace; second consecutive resets streak unless a freeze is available.
- **Daily time quests**: minutes ≥ min. Plan is a stretch goal (gold day).
- **Week start**: `cfg.weekStart` 0 = Sunday, absent = Monday. `weekStart(k)` honours it, so every weekly rule follows; use `wkOrder()` for weekday chip order, `wkEndDay()`/`DAYF` for "until Saturday/Sunday", `wkSpan()` for "Mon–Sun". `nextMonday(k)` means "next week start". Changing it regroups past weeks.
- **Total quests (`q.roll`, minutes per period)**: `q.per` = absent (week), `"2w"` (two weeks counted from `weekStart(rollFrom(q))`) or `"month"` (calendar month). `perStart/perEnd/perWorkDays/perWord` in rules/26-periods.js; `rollSum(id,k,q?)`, `rollNeed`, `weekTarget` (= this period's target) and `schLen` all use the period. Late-in-week start only applies to weekly ones. SCHEMA 11 marks `per`/`weekStart`.
- **Weekly-total quests**: by default a fixed week. Pace by the quest's ticked **work days** (`rollNeed`): need by day k = min(straight-line share = target × workdays elapsed / workdays in period, done-before-today + what's left ÷ remaining work days incl. today). So a surplus still covers empty days, but a shortfall is spread over the rest of the period instead of landing on the next day. First week prorated from `startOn || addedOn || firstSeen`. On non-work days `activeDefs` marks it `opt` + `off`: it sits in a collapsed "Off today" group (`pc-offopen`), never counts as done, and is left out of the schedule, Just 5 and Pick; extra time logged there still counts toward the week.
- **Start dates (`q.startOn`)**: hidden until then; listed under "Starting soon". Weekly totals created after Thursday noon default to next Monday.
- **Your day**: `cfg.day` = `{wake, bed}` (default 07:00–23:00); `cfg.dayOv` = `{date, wake, bed}` overrides one day. ## Design system (keep new UI consistent with this)
- **CSS is one file per screen** (`src/styles/`, joined in number order, which is the cascade order): `00-base` (fonts, page, type, `.stone`, `.sw`, inputs), `01-scenery` (`#fx`, themes, sky), `02-layout` (views, panels, columns), `03-header` (title bar, HUD, day strip, main nav, + button), `04-today` (quest list and phone rows), `05-timer` (running card, sprint), `06-modals` (sheets, menus, toasts, prompts), `07-subjects`, `08-editor` (quest editor, new quest, add sheet, tap-to-type), `09-schedule`, `10-progress` (badges, grove, trends, share, past day), `11-rulebook`, `12-settings`, `13-help`, `14-auth`, `15-splash` (and pull to refresh). In each file the plain rules come first, then one block per breakpoint at the end (`max-width: 720px` = phones, `620`, `420`, tablet `800–1099px`, `min-width: 1000/1100/1280px`, reduced motion, dark scheme); a few phone rules that must stay ahead of a later plain rule sit among the plain rules in their own `@media` block. Put new rules in their screen's file and phone tweaks in its 720px block. `!important` is only kept where removing it changes something (beating an inline style set by JS, keeping `[hidden]`/hidden-while-timing things hidden, or another important rule); raise a selector instead of adding one. **Prove a CSS refactor changes nothing** before committing: `cp -r dist /tmp/dist-before`, edit, `npm run build`, `node scripts/css-diff.mjs /tmp/dist-before dist` (~8 min; a run regex as third argument narrows it, e.g. `'^w360$'`). It lists differing elements with the changed properties and exits 1. The 2026-10 consolidation (38 history-named files → 16 screen files, 114 dead declarations and 33 empty rules removed, `!important` 171 → 84) passed it with 0 differences.

Every posted state, including `next` handoffs, carries `bg`. Stopping always goes through `focusOff()` (hides 901 and cancels the fallback 900) via `focusSync(true)`; the app also clears a leftover live notification on open when nothing is running.
- Android caveats: exact alarms need `SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM` (remove `USE_EXACT_ALARM` before Play Store); channel importance/sound are immutable once created — use a new channel id to change them.

## Testing patterns
- `openApp(page, { now, cfg, days, extra, hash })` installs a fake clock and seeds storage; then drive the real UI.
- Mock native plugins by defining `window.Capacitor = { isNativePlatform: () => true, Plugins: {...} }` in `addInitScript` (see `native.spec.mjs`, `pace.spec.mjs`).
- Prefer `expect.poll` / `toBeHidden` over fixed waits; parallel runs expose races.
- Phone layout tests use `test.use({ viewport: { width: 360|390 }, isMobile: true, hasTouch: true })`; hold-to-drag is CDP `Input.dispatchTouchEvent` + `page.clock.runFor(450)`; `extra: {"pc-doneopen": "1"}` expands the Done group.
- The fake clock advances in real time after `clock.install`, so a test that must *not* reach a timeout (the quick-drag half of `rows.spec`) calls `page.clock.pauseAt(...)` first; otherwise a loaded machine makes it flaky.
- A test that reseeds with a second `openApp` keeps the first run's localStorage — split it into two tests.
- `tests/fixture.mjs` is a realistic account (every quest type, subjects with history, Rulebook, busy times, a repeat, a month of days) shared by `crawl.spec` and `sync.spec`. `crawl.spec` is an opt-in exploratory crawl of every screen in three data states on phone and desktop (`CRAWL=1 npx playwright test tests/crawl.spec.mjs`, ~8 min) reporting uncaught and console errors; run it after big batches. It answers the day's to-do review first; its remaining step misses (a new quest refused by the 10-a-day limit, a past day or far-future step blocked by an earlier step's leftovers) are script artifacts, not app errors — check "pageerror"/"console" lines. `sanity.spec` holds the regression tests from the last sanity pass.
- Cloud sync tests never touch the network: `sync.spec` installs an in-memory `window.PCFB` (`fake` in `tests/fakecloud.mjs`) with `window.__cloud.remote(path, data)` to simulate another device and a Firestore-shape validator in `batch`. Both fakes persist across the app's sign-in/out reloads (`__fc` / `__fb` in localStorage), so preset init scripts start with `if (localStorage.getItem("__fc")) return;`; wrap an action that reloads in `reloadOn(page, fn)` and poll with `ev()` (an evaluate that tolerates a reload). `store(page)` in sync.spec reads the signed-in account's copy.
